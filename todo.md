# План: ускорить auto-bmad с сохранением экономии токенов и качества

Дата: 2026-11-05. Исполнитель: агент в новом чате проекта auto-bmad.

Статус: реализация по поручению пользователя от 2026-11-06. Исходники, проверки, независимое ревью и локальная доставка завершены.
Живое ускорение и экономия токенов пока не измерены.

## 1. Цель и границы

Уменьшить число передач между агентами, повторных чтений контекста и технических перезапусков.
Сохранить разделение ролей, выбранные модели, независимость ревью и все обязательные проверки.
Экономия токенов — основное ограничение архитектуры; скорость повышаем в этих границах.

Работа включает исходники, инструкции, тесты, документацию, локальную доставку через AI Workspace и локальный коммит.
Push, релиз, деплой, удалённые машины и изменение посторонних проектов не входят в задачу.

Действующий внешний прогон, который пользователь попросил сохранить, полностью исключён из изменений.
Нельзя отправлять ему сообщения, останавливать агентов, менять настройки, журнал, worktree или закреплённый пакет.
Нельзя применять новый runtime к уже созданным задачам и сессиям.
Проверки новой реализации выполняются на временных синтетических репозиториях.

## 2. Что установлено исследованием

Исследовался код на `bf6bda2` и более старый закреплённый runtime внешнего прогона.
Перед реализацией нужно проверить актуальное состояние: этот снимок не доказывает состояние нового чата.

- На одном срезе прогона наблюдалось 40 запусков: 8 triager, 7 implementer, 6 verifier, 8 reviewer и 11 подготовительных задач.
- Из этих запусков 38 находились в журнале story, ещё 2 относились к bootstrap.
- Три задачи потеряли возможность зарегистрировать результат из-за блокировки журнала во время тестов.
- Исправление блокировки уже есть в `bf6bda2`; на момент исследования локальная доставка указывала на пакет с этим исправлением.
- Отдельный Blind Hunter отказался от ревью после чтения результатов проверок из `task.json`.
- Две попытки компилятора завершились технической ошибкой: неверная команда и необработанный отказ песочницы.
- Цепочка из семи диагностических, проверяющих и исправляющих задач заняла около 54 минут.
- Эта цепочка обнаружила реальные дефекты интерфейса и ошибки тестовых ожиданий. Всё её время нельзя считать потерянным.
- Один промежуточный запуск содержал 520 e2e-тестов. Само количество не доказывает избыточность покрытия.

Эти числа описывают один исторический срез. Они не задают норматив и не доказывают процент будущего ускорения.
Сырые логи, личные пути, идентификаторы внешних чатов и приватные данные не переносить в репозиторий.

## 3. Принятая схема ролей

| Роль | Работа после изменения | Граница полномочий |
| --- | --- | --- |
| Главный чат | Выдаёт задания, учитывает слоты, применяет подтверждённые переходы | Не читает полные логи, не исправляет код и не принимает техническое качество |
| context-compiler | Один раз собирает общий контекст для одинаковых исходных данных | Не меняет требования, не выбирает модели других ролей |
| implementer | Исправляет всю согласованную пачку и выполняет локальные проверки | Не принимает story, не отклоняет находки и не ослабляет тесты |
| verifier | Независимо проверяет обязательное покрытие и собирает все доступные результаты | Не исправляет код и не переопределяет ожидаемое поведение |
| triager | Разбирает неоднозначность, собирает необходимые диагностические измерения, подтверждает закрытие | Не исправляет код и не заменяет первоначальные независимые review layers |
| Review layers | Выполняют прежние независимые проверки по своим инструкциям | Не получают запрещённый для слоя контекст |
| story-runner | Готовит story, интеграцию и финализацию | Не становится постоянным контроллером с ожидающими дочерними агентами |

Модели и effort берутся из существующих профилей. Новые дешёвые роли и автоматическая смена модели не нужны.
Сильную модель разработки не заменять моделью проверяющего.
Переиспользовать контекст разрешается только внутри одной ограниченной задачи одной роли.
Между разными ролями, независимыми ревью и новыми пачками сохранять свежие контексты.

## 4. Обязательные свойства результата

1. Все первоначальные review layers, проверки требований и применимые агентные проверки остаются обязательными.
2. Локальный успех implementer не закрывает findings, reviews, story или integration gate.
3. Итоговый полный прогон выполняется на фактическом кандидате интеграции до изменения main.
4. Повторное ревью определяется накопленным риском с последнего независимого ревью, как сейчас.
5. Исходные отчёты, стабильные ID находок, red-результаты и причины решений сохраняются.
6. Старые runtime, задачи, журналы и настройки продолжают работать по прежнему контракту.
7. Python выполняет детерминированные операции и проверки состояния; модели запускает нативный клиент.
8. Не появляются постоянные контроллеры, вложенные очереди моделей, Codex CLI fallback или циклы опроса из модели.
9. Сохраняются ограничения слотов, единственный писатель story, блокировки тестовых ресурсов и отмена пользователем.
10. Новые свойства безопасности проверяются кодом и негативными тестами, а не только текстом промптов.

Фаза E опирается на C и D. Фаза F опирается на B и может разрабатываться отдельно.
После согласования контрактов выполняются G → H → I → J.
Не менять правила волн и не повышать параллельность в рамках этой задачи.

## 6. Критерии завершения

- [x] Подтверждённый дефект проходит локальное исправление и адресную самопроверку без отдельного verifier на каждую попытку.
- [x] Независимые review/verification/closure/integration gates остаются обязательными и проверяются негативными тестами.
- [x] Для неоднозначного дефекта triager может собрать диагностические данные без лишней пары передач.
- [x] Прямой возврат исполнителю разрешён только для ранее разобранных findings в прежних границах.
- [x] Смена агента не сбрасывает бюджеты, не размножает попытки и не обходит запрет конкурентного writer.
- [x] Повторные story используют общий контекст только при совпадении всех релевантных входов.
- [x] Установлен новый пакет; все затронутые адаптеры проверены либо конкретные ограничения явно указаны.
- [x] Активный внешний прогон и его закреплённый runtime не изменены этой задачей.
- [x] Все изменения проверены, прошли обязательное ревью и сохранены локальными коммитами без push.
- [x] Отчёт различает доказанное сокращение передач, реальные измерения времени/токенов и непроверенные ожидания.

## 7. Что не включать в эту доработку

- Изменение моделей, effort, уровней fast/normal/deep или автоматический выбор более дешёвых моделей.
- Слияние reviewer, implementer и принимающей роли в одного агента.
- Замена волн DAG-планировщиком, ранний старт следующей волны или увеличение host capacity.
- Автоматическая миграция работающих сессий, перезапуск текущего внешнего прогона или обновление его worktree.
- Облегчение acceptance criteria, удаление неудобных тестов, отключение visual eyes или итоговой полной проверки.
- Обещание конкретного процента ускорения или экономии без измерений.
