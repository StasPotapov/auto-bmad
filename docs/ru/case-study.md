# Пример: Android-приложение за 10 часов

[English](../en/case-study.md) · [Назад к README](../../README.ru.md)

На этой странице — настоящий прогон auto-bmad. Человек подготовил план в BMad, а
приложение с нуля написал auto-bmad: 4 эпика, 28 story, около 10 часов работы без
участия человека. Все цифры взяты из `auto-bmad stats` и истории git.

## Проект

Проект — Android-игра для компании: пары угадывают слова на одном телефоне. В нём есть турнир на
много пар, раунды с таймером и подсчётом очков, 14 готовых словарей и свои словари.
Свой словарь можно набрать руками, вставить из буфера, загрузить из файла и выгрузить.
Ещё есть настройки: палитра, звук, вибрация и язык.

Стек: Kotlin, Jetpack Compose, Room, DataStore, Koin. Минимальная версия — Android 10.

## Что сделал человек

1. Подготовил план в BMad: бриф, PRD, UX, архитектуру, эпики и sprint planning.
   Итог — 5 эпиков и 31 story.
2. Запустил `/auto-bmad:setup`. Он записал `.auto-bmad.toml`: уровень `normal`,
   параллельные волны `conservative`, тесты `./gradlew test` и проверку на эмуляторе
   API 35 через [adbm](https://github.com/StasPotapov/adbm).
3. Запускал `/auto-bmad:auto-bmad epic-N` по одному эпику и смотрел результат.

Код человек не писал. Эпик 5 — это подготовка к Google Play: подпись релиза, политика
конфиденциальности, плавность свайпа на Android 10. Его пока не запускали.

## Результат

| | |
|---|---|
| Эпики и story | 4 эпика, 28 story, все `done` |
| Время прогона | 9 ч 57 мин (с 14:16 до 02:50 следующего дня, с перерывами между эпиками) |
| Остановки | одна: первую story остановил предполёт. Лишний модуль BMad ломал движок, человек убрал его за 3 минуты |
| Коммиты | 62: коммит на story, коммит трекинга, одна починка по проверке |
| Kotlin, код приложения | 16,6 тыс. строк, 148 файлов |
| Kotlin, тесты | 10,3 тыс. строк, 628 тестов |
| Словари и ресурсы | 3,1 тыс. строк словарей, 1,1 тыс. строк ресурсов |
| Проверки на эмуляторе | 25 проверок: 24 прошли сразу, одна нашла проблему |
| Ревью | 868 находок, ни одной `high`, 31 `medium`; остальное — `low` и ложные |
| Вопросы человеку | 93 пункта в файлах `epic-<N>-open-questions.md` |

Проверка нашла проблему в story 2-4: карточка последнего слова ломалась при крупном
шрифте. Движок починил её за один заход, повторная проверка прошла.

Вопросы человеку — это то, что агент не решает сам. Например, требование вычитать
14 готовых словарей руками и выбор поведения кнопки «Назад» на корневом экране.

## Оценка человека

Приложение работает так, как описано в плане, ошибок в логике автор не нашёл.
Его субъективная оценка — 99%. Недочёты нашлись только в нескольких анимациях: на ходу
анимации часть элемента обрезается. Такие дефекты модель плохо видит на статичных
кадрах, а руками они чинятся быстро.
