# Запуск

[English](../en/running.md) · [К README](../../README.ru.md)

> **Язык.** Прогон говорит с вами на **языке прогона**: строки прогресса, отчёты и пункты
> файла открытых вопросов. Язык прогона — `communication_language` из BMad
> в том порядке, в каком его читает сам BMad: `_bmad/custom/config.user.toml`,
> `_bmad/custom/config.toml`, `_bmad/config.user.toml`, `_bmad/config.toml`, затем старые
> файлы настроек BMad.
> Если он не задан, прогон берёт язык, на котором вы пишете. Прогон без человека
> без заданного языка пишет по-английски. Сообщения коммитов, машинные метки
> (`WORK_START`, `STORY_DONE`…) и служебный текст файла открытых вопросов всегда
> английские.

## Аргументы

```
/auto-bmad:auto-bmad [story-id | epic-N | пусто] [--fast | --normal | --deep]
                     [--parallel-fast [N]] [--width N] [--no-parallel]
```

| Аргумент | Что идёт в прогон |
|---|---|
| `epic-1` (или `epic 1`, или «эпик 1») | все истории эпика 1, которые ещё не `done`: сначала истории в `review`, потом остальные по порядку номеров; ретроспектива пропускается |
| `1-3` (или `1.3`, `story 1-3`; разделённая story BMad: `2-6a`) | одна story |
| пусто | story по умолчанию: первая `in-progress`, иначе первая `review`, иначе первая `ready-for-dev`, иначе первая `backlog` из эпика в статусе `in-progress`, иначе вообще первая `backlog` |

Пара `N-M` или `N.M` — это story. У номера story может быть буква разделённой story (`2-6a`). Одно слово и одно число (`epic-7`, `epic 7`, «эпик 7»)
или просто число — это эпик. Другое, например `story 7` или `fix bug 12`, прогон
не угадывает: он спросит, что вы имели в виду.

| Флаг | Что делает |
|---|---|
| `--fast`, `--normal`, `--deep` | глубина ревью на этот прогон, см. [Уровни](levels.md). Два разных уровня сразу — ошибка |
| `--no-parallel` | истории эпика идут по одной |
| `--parallel-fast [N]` | агрессивный отбор историй в волну; число после флага — размер волны |
| `--width N` | размер волны (по умолчанию 3) |

Флаги главнее секции `[run]` конфига (см. [Конфиг](config.md#run)). Нет ни флагов,
ни конфига — уровень `normal`, параллель `conservative`, ширина 3. Старый флаг `--parallel`
снят. Прогон предупредит о нём, а число после него возьмёт как ширину.

Примеры:

```
/auto-bmad:auto-bmad epic-1
/auto-bmad:auto-bmad epic-2 --deep --no-parallel
/auto-bmad:auto-bmad epic-3 --fast --width 4
/auto-bmad:auto-bmad 1-3
/auto-bmad:auto-bmad
```

## Зависимости эпиков

Эпик может сказать, чего он ждёт. Для этого под его заголовком в файле эпиков пишут строку:

```markdown
## Эпик 3: Отчёты

**Waits:** epic 2
```

Подходят и `Waits for:`, `Depends on:`. Строку пишут по-английски в проекте на любом языке:
скрипт читает слова `epic`, `story` и `and`. Перед прогоном auto-bmad
сверяет строку с `sprint-status.yaml`:

- весь эпик ждёт то, что ещё не `done`, — прогон не начинается и говорит, чего ждёт;
- условие только на часть историй (`**Waits:** 3.4–3.6 — epic 2`) — очередь обрывается перед
  первой такой историей, причина попадает в финальный отчёт. Диапазон включает разделённые
  story внутри: `3.4–3.6` покрывает `3.5a`, а `3.5a–3.5c` — `3.5a`, `3.5b`, `3.5c`.
  Разделённую story можно назвать и отдельно: `story 2.6a`;
- условие словами, которое скрипт проверить не может, считается невыполненным.

## Что происходит со story

До первой истории прогон:

1. Разбирает аргумент и собирает очередь из `sprint-status.yaml`. Заголовки и цели
   историй берёт из файла эпиков. Его заголовки — в формате BMad: `## Epic <N>: <название>`
   и `### Story <N>.<M>: <название>` (разделённая story: `### Story 2.6a: …`), ключевые слова английские, название на любом языке.
   Те же заголовки читает sprint planning самого BMad (см. [CLI](cli.md#plan)).
2. Шлёт хукам событие `run-start`.
3. Делает **предполёт** (см. [CLI](cli.md#preflight)): чистое дерево, движок BMad,
   `sprint-status.yaml`, `_bmad/custom/`, `uv`, агент-типы плагина. Чего-то нет — прогон
   встаёт. Грязное дерево прогон покажет вам, но сам не коммитит и не откатывает вашу работу.
4. Пишет **профиль уровня** в `_bmad/custom/bmad-build-auto.user.toml`. Файл закрыт от git
   локально, через `.git/info/exclude`. Если этот файл писал человек, прогон его не трогает
   и останавливается.
5. Один раз гонит тесты проекта — это **baseline** (на `fast` не гонит).
6. Печатает уровень и таблицу историй, которые возьмёт.

Дальше по каждой story видна строка прогресса:

```
[Story 2/5] ✅ Предполёт → ⏳ Прогон story → ⬚ Проверка → ⬚ Синк спринта → ⬚ Отчёт
```

Подписи шагов идут на языке прогона. Значки ✅ ⏳ ⬚ и стрелки не меняются.

| Шаг | Что происходит |
|---|---|
| 1. Предполёт | Повторяется перед каждой историей. Потом событие хукам `story-start` |
| 2. Прогон story | Новый сабагент `auto-bmad:bmad-story-runner` гонит движок BMad `bmad-build-auto`: спека → код → слои ревью → разбор находок и починка → проверки из спеки → коммит. Повторные проходы ревью — в пределах лимита уровня. Наверх приходит только короткий отчёт, поэтому контекст между историями не копится |
| 3. Итог | `done` или `blocked` |
| 3.5. Проверка | На `normal` и `deep`: тесты проекта и другие проверки из конфига. Нашли проблему — движок чинит, проверка повторяется. См. [Проверки](checks.md) |
| 4. Синк спринта | Story становится `done` в `sprint-status.yaml`, статус эпика поднимается следом. Открытые вопросы story уходят в файл эпика. Один коммит. Потом событие `story-done` |
| 5. Отчёт | Отчёт по story и запись её статистики |
| 6. Дальше | Следующую историю прогон берёт сам, не спрашивая. Остановить его может только окно времени (см. [Прогон без человека](unattended.md#окно-времени-и-лимиты-подписки)) |

Story ушла в `blocked` — эпик останавливается. Её разбор уходит в файл открытых вопросов
(с коммитом), хукам идёт событие `story-blocked`, в отчёте — список того, что осталось.

Каждый отчёт по story кончается машинной строкой для внешних раннеров:
`STORY_DONE: <id> commit=<sha> files=<n>`, а у остановленной story — `STORY_BLOCKED: <id>`
(см. [Примеры интеграций](examples.md#метки-в-выводе)).

Push прогон не делает никогда. Коммиты за прогон:

- коммит движка с кодом story;
- коммиты починки после проверки (правка спеки, потом починка движка);
- коммит со сценарием, который оставила проверка (например, Maestro-flow adbm);
- коммит трекинга спринта (вместе с файлом открытых вопросов);
- в параллельном режиме — коммиты мержа.

## Отчёты

Отчёт по story пишется для читателя, который не знает ни кода, ни BMad. В нём три части:

- **Что сделано** — простыми словами, глазами пользователя программы;
- **Как проверить** — шаги по номерам: что запустить, открыть, нажать и что должно получиться;
- **Требует внимания** — только решения для человека. Каждый пункт в одной форме:
  что не так → чем грозит → 2–3 варианта с ценой → рекомендация.

В конце эпика — отчёт по эпику: что теперь умеет программа, строка на каждую story с её
коммитом, общий сценарий проверки, все пункты «требует внимания» сводно и по важности,
три строки статистики прогона и что дальше (`bmad-retrospective`, `auto-bmad stats show`,
`bmad-walkthrough`).

## Файл открытых вопросов

Пункты «требует внимания» живут не только в чате. После каждой истории они уходят
в один файл на эпик:

```
_bmad-output/implementation-artifacts/epic-<N>-open-questions.md
```

Секция на каждую story, у секции — ссылка на спеку и коммит. Остановленная story тоже
получает секцию, с пометкой `(blocked)`. Файл коммитится вместе с трекингом спринта.

Файлом владеет скрипт. Секция истории стоит между якорями:

```markdown
<!-- story:1-3 -->
## Story 1-3 — импорт CSV
...
<!-- /story:1-3 -->
```

У разделённой story своя секция с буквой: `<!-- story:2-6a -->`. Повторный прогон той же story заменяет только её секцию. Ваши заметки вне якорей остаются.
Если файл с таким именем создал не auto-bmad, прогон его не трогает.

## Продолжение прерванной story

Запустите ту же команду снова. Перед story прогон ищет её спеку:

| Статус спеки | Что делает прогон |
|---|---|
| спеки нет | начинает story с нуля |
| `draft`, `ready-for-dev`, `in-progress`, `in-review` | отдаёт движку путь к спеке. Движок продолжает с того шага и не переделывает готовое. В чате будет строка вроде «Story 3-7: продолжаю прерванную работу (спека в статусе in-review)» |
| `done`, story в `review` в `sprint-status.yaml` | код закоммичен и ждёт ревью: отдаёт движку путь к спеке. Движок делает новый проход ревью, чинит найденное и коммитит. В чате будет строка вроде «Story 5-1: ревью готового кода (статус review в трекинге)» |
| `done`, другой статус в трекинге | работа сделана, отстал только трекинг: синк `sprint-status.yaml` без движка |
| спеки нет, story в `review` в `sprint-status.yaml` | код написан не движком, спеки для ревью нет: показывает вам и останавливается |
| `blocked` или неизвестный | показывает вам и останавливается |
| две спеки и больше на одну story | показывает список и спрашивает, какая настоящая |

## Параллельные волны

В режиме эпика параллель включена по умолчанию. Прогон делит очередь на **волны**.
Истории одной волны идут одновременно, каждая в своём git worktree в `.claude/worktrees/`
и на своей ветке `auto-bmad/<story-id>`. Волны идут строго одна за другой. Порядок
историй сохраняется: волна — всегда непрерывный кусок очереди с начала.

| Режим | Какие истории идут в одну волну |
|---|---|
| conservative (по умолчанию) | только истории без признаков пересечения: нет явной зависимости, общего файла или модуля, связи «одна создаёт — другая использует», общей точки сборки (конфиг, роутер, DI, миграции, схема БД), непонятной области изменений |
| aggressive (`--parallel-fast`) | всё, кроме явной зависимости и общей точки сборки. Пересечение по файлам разбирается на мерже |

В волне не больше `N` историй (по умолчанию 3). До первой волны прогон показывает
таблицу волн. У истории, которую отодвинули в волну позже, написана причина.

После волны оркестратор:

1. Мержит ветки по одной, в порядке очереди (`git merge --no-ff`). Конфликт решает сам,
   с минимальной правкой, и каждое решение пишет в «требует внимания». Не уверен — отменяет
   этот мерж и спрашивает вас. Остальные истории волны мержатся дальше.
2. Убирает смёрженные worktree и ветки, потом гонит тесты проекта на сведённом коде.
   Тесты упали при зелёном baseline — эпик останавливается. Прогон их не чинит
   и мерж без вашего слова не откатывает.
3. Гонит остальные проверки (устройство, свои) по каждой смёрженной истории, по одной.
4. Синк `sprint-status.yaml` и файла вопросов — один коммит на волну. Потом события
   `story-done` / `story-blocked` на каждую историю и одно `wave-merged`.

Story в `blocked` не отменяет мерж остальных. Её ветка и worktree остаются,
а эпик останавливается после этой волны.

### Когда прогон идёт по одной

- `--no-parallel` или `parallel = "off"` в `[run]`;
- прогон одной story, или в очереди осталась одна история (волна из одной истории идёт
  как обычный последовательный прогон);
- файлы движка (`.claude/skills/bmad-build-auto/SKILL.md`, `_bmad/scripts/render_skill.py`)
  не в git, и в новом worktree их не будет. Предполёт назовёт причину (правило игнора или
  незакоммиченный файл) и починку. Прогон пойдёт по одной и повторит починку в финальном отчёте;
- сабагент истории сообщил, что своего worktree не получил, — остаток волны идёт по одной.

В репозитории нет `origin`, а настройка Claude Code `worktree.baseRef` равна `fresh`
(это умолчание) — создание worktree может не пройти. Предполёт об этом предупредит.
Поставьте `worktree.baseRef` = `head` через `/config`.

Ваши тесты обходят файлы на диске (ищут дубли, TODO и подобное)? Тогда они увидят копии кода
в `.claude/worktrees/`. Предполёт предупредит, если ни один конфиг тестов не упоминает
`.claude`. Исключите эту папку в настройках тестов.

### Параллельный прогон оборвался

Работа оборванной волны лежит в ветках `auto-bmad/<story-id>`, а не в основном дереве.
Предполёт покажет оставшиеся worktree. Прогон разберёт их вместе с вами, по одному:
готовую историю смёржит, недоделанную можно продолжить с её ветки или начать заново,
пустую уберёт. Ничего с коммитами без вашего слова не удаляется.

Уборка руками:

```bash
auto-bmad worktree list --repo .
auto-bmad worktree remove --path <путь> --repo .
```

`--force` сносит и незакоммиченную работу в этом worktree.

## Прогресс в интерфейсе Claude Code

Прогон ведёт список задач: задача на каждую story плюс финальный отчёт (режим эпика)
или задача на каждый шаг (режим story). Если инструментов задач в сессии нет, прогресс
идёт только текстом. Прогон скажет, что список включается переменной
`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` в `~/.claude/settings.json`.
