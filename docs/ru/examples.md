# Примеры интеграций

[English](../en/examples.md) · [Назад к README](../../README.ru.md)

Автор запускает auto-bmad с доской задач, ночными прогонами с уведомлениями в чат и скиллом,
который берёт отдельные задачи из трекера. Ничего из этого в плагине нет. Каждая схема
собрана из того, что даёт плагин: [хуки](hooks.md), [конфиг](config.md),
[метки в выводе](#метки-в-выводе) и агент `auto-bmad:bmad-story-runner`. Берите их как образец
для своей схемы.

## Синк доски задач — хук

Хук отражает прогон на доске Gitea на своём сервере. Эпик становится вехой, story — задачей,
и карточка идёт по колонкам вместе с прогоном.

```toml
# ~/.config/auto-bmad/config.toml — личный слой, поэтому хук получает каждый проект
[[hook]]
name = "board"
events = ["run-start", "story-start", "story-done", "story-blocked"]
command = "python3 ~/hooks/board_sync.py"
```

| Событие | Что делает хук |
|---|---|
| `run-start` | проверяет, подключён ли проект к доске. Если нет и человек рядом, возвращает `ask` с вариантами «подключить», «подключить все» и «не подключать» |
| `story-start` | при необходимости заводит задачу и переводит её «В работу» |
| `story-done` | читает `## Auto Run Result` из спеки и секцию story из `questions_file`. Затем пишет отчёт в задачу, переводит её «На проверку» и ставит метку «вопросы», если у story есть открытые вопросы |
| `story-blocked` | ставит метку «заблокировано» и пишет, на чём story встала |

Хук никогда не останавливает прогон. При любой ошибке он возвращает `"ok": false`
с `message` и выходит с кодом 0. auto-bmad показывает сообщение, и прогон идёт дальше.

## Ночные прогоны с уведомлениями — внешний раннер

Планировщик на домашнем сервере гоняет эпики ночью и пишет в чат-бота. Бот также умеет
запустить прогон сейчас или поставить его на ночь.

1. Перед сеансом раннер обновляет плагин: `git pull` в клоне плагина, затем
   `claude plugin update auto-bmad@auto-bmad`.
2. Раннер запускает `claude -p "/auto-bmad:auto-bmad epic-N --normal"` с окном времени
   и лимитами из [Прогона без человека](unattended.md#окно-времени-и-лимиты-подписки):
   `AUTO_BMAD_DEADLINE`, `AUTO_BMAD_RESERVE_MINUTES`, `AUTO_BMAD_LIMITS_FILE`,
   `AUTO_BMAD_STOP_AT_FIVE_HOUR_PCT`, `AUTO_BMAD_STOP_AT_SEVEN_DAY_PCT`.
3. Раннер читает вывод `stream-json` построчно. На каждую метку он шлёт сообщение в чат
   (таблица ниже).
4. Раннер берёт выработку подписки из строк `rate_limit_event` потока и пишет её
   в `AUTO_BMAD_LIMITS_FILE`. auto-bmad читает этот файл между историями и у лимита
   перестаёт брать новые.
5. Пока в окне есть время, раннер запускает следующий эпик.

### Метки в выводе

auto-bmad печатает эти строки дословно, каждую отдельной строкой, на любом языке прогона.

| Метка | Когда | Что может сделать раннер |
|---|---|---|
| `WORK_START: story <id>` или `WORK_START: wave <n> (<ids>)` | взята story или волна | если окно уже кончилось, остановить прогон: нарушено правило «после окна ничего не брать» |
| `STORY_DONE: <id> commit=<sha> files=<n>` | последняя строка отчёта по story | написать «story готова» с коммитом |
| `STORY_BLOCKED: <id>` | последняя строка отчёта «story остановлена» | прислать тревогу |
| `WINDOW_STOP: epic-<N> done=<X> left=<Y>` | последняя строка прогона, остановленного по окну | считать прогон штатной остановкой, а не обрывом |

Журнал событий (`AUTO_BMAD_EVENTS_FILE`, см. [Хуки](hooks.md#журнал-событий)) даёт те же
факты строками JSON, если файл удобнее потока.

## Одна задача из трекера — свой скилл и story runner

Личный скилл берёт задачу по номеру и прогоняет её через тот же движок, вне эпика. Он
пользуется CLI плагина и агентом `auto-bmad:bmad-story-runner` в режиме задачи.

1. Проверьте проект и соберите профиль уровня:

   ```bash
   auto-bmad preflight --repo .
   auto-bmad profile --level normal --repo .
   ```

2. Запустите `Agent` типа `auto-bmad:bmad-story-runner` с таким промптом:

   ```
   Run one task through the BMad engine and return a report by your type's contract.

   Task: #12 — Экспорт словаря в файл
   Spec slug: issue-12
   Run level: normal
   Review pass limit: 2
   Project root: /path/to/project
   Language: Russian

   <текст задачи и комментарии как есть>
   ```

   Движок назовёт спеку `spec-issue-12-….md`. При повторном вызове передайте
   `Spec: <путь>`, и раннер продолжит ту же спеку.
3. После `STATUS: done` прогоните проверки, как в Step 3.5 скилла:
   `auto-bmad verify plan`, затем проверки, затем цикл починки. В промпте проверки пишите
   `Story: issue-12 — <заголовок>`: тогда статистика отнесёт проверку к той же задаче.
4. Напишите отчёт в задачу и переведите карточку.

`auto-bmad stats record` считает такой прогон задачей, а id берёт из слага спеки.
